# 상태 소유 기준과 적용 결과

## 기준

| 상태 종류                                 | 위치                                      | 예시                                                                     |
| ----------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------ |
| 서버가 소유한 데이터                      | entity queryOptions + TanStack Query 캐시 | 부원 목록·집계, 트랙 상세, 커리큘럼 트리                                 |
| 새로고침·링크·뒤로가기로 복원할 조회 상태 | Router의 검증된 search params             | 인명부 필터·검색·페이지·정렬, 활동 카테고리, 커리큘럼 선택, 게임 상세 탭 |
| 편집 중이며 아직 확정되지 않은 값         | 편집 컴포넌트 로컬 상태                   | 검색 입력 초안, 헤더 폼, 업로드 파일                                     |
| 한 화면에서만 쓰는 일시적 UI              | 가장 가까운 공통 부모 또는 해당 컴포넌트  | 모달 열림, 카드 펼침, 드래그 중 순서                                     |
| 화면·브라우저 탭에서 공유하는 사용자 설정 | 외부 저장소를 구독하는 전역 상태          | 테마                                                                     |
| 다른 상태에서 계산할 수 있는 값           | 렌더 중 계산                              | 선택된 서버 객체, 첫 주차, 권한, 집계 표시                               |
| 요청 진행·실패                            | Query/mutation 결과                       | isPending, isError, error                                                |

## 적용

- 인명부의 filters/page/sort/direction을 로컬 state에서 제거했다. URL을 검증한 값으로 API query key를 만든다. 검색 입력 중 초안은 Toolbar에만 두며 300ms 후 URL에 반영한다. URL 복원 시 타이머를 취소하고 입력 포커스를 유지한다. 필터·검색·정렬 변경은 첫 페이지로 이동하고, 서버 응답으로 페이지 범위가 줄면 replace 이동으로 보정한다. 기존 placeholder 목록 유지 동작은 보존한다.
- 활동 카테고리 선택을 URL로 옮겼다. 카테고리 객체는 Query 목록에서 찾고, 폼은 ID별 로컬 초안으로 유지한다.
- 커리큘럼의 트랙·세트·명시적으로 선택한 주차를 URL로 옮겼다. 삭제되거나 미선택인 주차의 첫 항목 선택은 계산값이며 state 동기화 코드가 필요 없다. 트랙→세트→주차 변경 시 하위 선택을 원자적으로 제거한다. URL의 ID는 서버 목록의 소속 관계까지 확인한 뒤 종속 쿼리를 활성화한다. 편집기와 모달은 상위 선택에 맞춰 초기화한다.
- 게임 상세 탭을 URL로 옮겼다. 탭별 편집 초안은 각 패널이 계속 소유한다.
- 인명부 활동 mutation과 활동 헤더 mutation의 중복 error state를 제거했다.
- 테마 토글별 로컬 state를 제거했다. useSyncExternalStore로 localStorage를 구독하며 같은 탭 이벤트와 다른 탭의 storage 이벤트를 반영한다.

## 쿼리와 편집 경계 추가 정리

- 예약 현황의 월 점유·일별 예약은 현황 화면, 내 월 점유는 내 예약 화면, 과거 목록은 내 예약의 과거 탭에서만 활성화한다. 예정 목록은 현재 목록 및 내 예약 탭의 건수 배지에 쓰며 규칙 화면에서는 요청하지 않는다. 로딩·오류도 선택한 목록을 기준으로 표시한다.
- 예약 query key를 공통 reservations 루트 아래로 묶고 mutation 뒤 루트 전체를 무효화한다. 비활성인 다른 월·날짜·상세는 즉시 요청하지 않고 다음 활성화 때 갱신한다.
- 활동 저장·공개 변경은 필요한 invalidate를 Promise.all로 기다린다. 저장·삭제 모달은 목록·집계 갱신 후 닫는다. 삭제한 상세는 재조회 대신 캐시에서 제거한다.
- 모집 링크는 서버 데이터 준비 후 편집기를 마운트한다. 초기화 플래그를 없애고 편집 중 background refetch에도 로컬 초안을 보존한다.
- 첫 트랙 이동은 index loader에서만 결정한다. loader는 오래된 캐시를 그대로 사용하지 않고 fetchQuery로 목록을 확인한다. 이미 열린 빈 목록이 재조회로 채워지면 앱의 Query 캐시 구독이 index loader만 invalidate한다. 페이지의 별도 navigate effect는 제거했다.

## 유지한 상태

- 세션 store는 앱 전반의 인증에 쓰이므로 전역에 둔다. 토큰을 URL로 옮기지 않는다.
- DuesUiProvider는 장부·회비 화면을 이동한 후 표시할 일회성 토스트를 공유하는 영역 상태다. 서버 데이터를 보관하지 않으므로 현재 범위를 유지한다.
- 서버 데이터를 편집용으로 복사한 폼은 사용자 초안이므로 로컬 상태로 유지한다. background refetch가 작성 중인 값을 덮어쓰지 않게 한다.
- 모달 열림, 확장, 파일 선택, 임시 순서는 공유·복원이 필요한 탐색 상태와 구별한다.

## 장부·회비·면제 사유·예약

| 화면      | URL 상태                                          | 로컬 상태                                            |
| --------- | ------------------------------------------------- | ---------------------------------------------------- |
| 장부      | 검증된 filters, entryId                           | 날짜 입력 중간값, 거래 편집, 가져오기 파일·검토 초안 |
| 회비      | 학기 경로, members/tracks/errors/states, memberId | 옵션 검색, 명단 변경·거래 연결·학기 생성 초안        |
| 면제 사유 | view, semester, filters                           | 옵션 검색, 면제 등록·수정 단계와 초안                |
| 예약      | screen, month, date, tab, detailId                | 시간·목적·인원·반복 설정·동의, 기존 예약 교체 의도   |

- 서버 응답은 Query 캐시에 유지하며 선택 객체와 필터 결과는 응답과 URL에서 계산한다. 존재하지 않는 거래·회원 선택은 상세를 열지 않는다.
- 날짜·월·ID·열거형은 URL 검증을 통과한 값만 사용한다. 장부 날짜 입력의 미완성 값은 로컬에 두고 완성된 날짜나 빈 값만 URL에 반영한다.
- 장부 거래 편집·가져오기, 회비 명단·거래 연결, 면제 작성 초안이 있는 경우 이탈과 취소 시 확인한다. 저장 후 정상 종료는 추가 확인을 요구하지 않는다.
- 예약 작성 상태는 화면·월·내 예약 탭·상세 전환 중 유지한다. 선택 날짜 변경이나 다른 페이지 이동은 확인하며, 날짜가 바뀌면 초안을 초기화한다. 규칙 탭을 확인하고 돌아와도 초안은 유지된다.
- 새로고침·브라우저 닫기는 작성 중 경고를 사용한다. 초안을 URL에 넣거나 전역 store에 복사하지 않는다.
- 예약 변경 뒤에는 방문했던 다른 월·날짜·상세 캐시도 무효화한다. 반복 예약이 현재 조회 범위 밖에 영향을 주어도 재방문 시 갱신된다.
- 거래 연결의 자동 추천은 서버 목록에서 계산하고 사용자가 바꾼 선택만 로컬에 저장한다. 비동기로 목록이 도착해도 추천 값이 초기 state에 갇히지 않는다.
